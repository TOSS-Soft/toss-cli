## Correctness Equivalence

The public eager and demand-driven validators were compared for byte-equivalent
results, including canonical serialized results, across an empty invalid value
for each of all 37 logical schema IDs. The comparison also covers valid and
invalid examples from the common, PM analysis, issue-plan, design, and command
result families.

The retained cases exercise canonical-JSON rejection for non-JSON JavaScript
values, closed-shape additional-property rejection, valid and impossible
RFC3339 timestamps, internal and external references, unknown schema IDs, and
normalized Ajv errors. The demand-driven validator preserves the synchronous
public API and the eager reference's returned result or thrown-error shape for
each comparison.

## Decision

Select `demand-driven`. The saved decision was reproduced directly with
`selectValidatorStrategy`; it was not hand-edited. The exact reason code is
`STANDALONE_FOCUSED_GAIN_UNPROVEN`.

Reject `eager-reference` because it performs schema I/O and registration for
unused schema families on runtime construction. Reject `standalone-experiment`
because no standalone production candidate and therefore no three-sample
standalone focused-gate capture exists. The one-schema experiment was
deterministic and result-equivalent, but `standalone_drift_verified` remains
`false`: it does not verify deterministic generated output against all 37
catalog schemas. No standalone focused performance is claimed.

## Command Boundary Retention

All ten issue-28 command cases continue through the public parser and dispatcher
in process, retaining their exact service profiles, exit codes, valid
`command-result.v1` envelopes, and error boundaries. Two production-binary
sentinels remain as guarded fresh processes. The preload denies actual fetch,
HTTP(S), TCP, TLS, and DNS access, so those sentinels retain the real binary
boundary without permitting network access.
