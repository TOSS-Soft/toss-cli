# TOSS CLI v2.1.0 Agent Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Complete baseline issue #33 and GitHub issues #12–#32 through one sequential pull request per issue, then publish TOSS CLI v2.1.0 to npm, GitHub Packages, and GitHub Releases.

**Architecture:** Versioned JSON Schemas and semantic validators define provider-neutral agent contracts. Immutable filesystem artifacts feed deterministic analysis, audit, traceability, readiness, GitHub publication, and UI/UX design pipelines; focused CLI modules expose those services while preserving legacy scaffold commands.

**Tech Stack:** Node.js ESM (engine floor 20, CI 24), Node test runner, Ajv 8.20.0 with JSON Schema 2020-12, YAML 2.x, SHA-256, atomic filesystem writes, authenticated GitHub CLI, GitHub Actions

## Global Constraints

- Release version is exactly 2.1.0; the final tag is exactly v2.1.0.
- Every issue has its own branch, commit set, pull request, required test check, and merge.
- Each issue branch starts from the latest merged origin/main; no unmerged branch is stacked.
- Canonical representation is JSON; YAML is a lossless input/human projection.
- Artifacts are immutable, revisioned, provenance-bearing, and fail closed on corruption or unknown versions.
- PM owns requirements; Architect owns ADRs; Spec Auditor and Design Auditor only emit findings.
- No embedded model vendor, API key, or network model call is added.
- GitHub issue preview is read-only; publication is dry-run unless explicit --apply passes every gate.
- Existing toss init, toss create, and fast scaffold behavior remains compatible.
- The parent ChatGPT project's sources directory remains read-only and outside this repository.
- Implementers stop after the local commit and report the commit and checks to the controller. The controller performs task review, then push, PR, CI, and merge; no task may merge before review.

## File Map

- contracts/common/: artifact envelope, entity, reference, provenance, and question schemas.
- contracts/agents/: PM analysis, architecture, ADR, issue plan, audit, and finding schemas.
- contracts/pipeline/: decisions, trace graph, transitions, readiness, publication result, and command result schemas.
- contracts/design/: design lifecycle schemas required by #29–#31.
- docs/contracts/: normative ACP, CLI, state-machine, audit-boundary, and authority documents.
- src/contracts/: canonical JSON/YAML projection, schema registry, Ajv validation, and semantic validation.
- src/artifacts/: immutable revision store and integrity/recovery behavior.
- src/pipeline/: PM, architecture, planning, decisions, audit, graph, state, readiness, publication, and design services.
- src/commands/: lifecycle command parser, handlers, and service wiring.
- src/output/: stable JSON envelope and terminal renderers.
- test/*.test.js: behavioral and contract tests run by Node's test runner.
- test/fixtures/: deterministic valid/invalid artifact graphs and CLI inputs.
- README.md: user workflows and command reference.
- docs/releases/v2.1.0.md: release notes and evidence checklist.

## Repeated Pull Request Gate

Every issue task ends with the following sequence using the exact files, branch,
commit message, and issue number stated in that task:

    npm test
    npm pack --dry-run
    git diff --check
    git status --short
    git diff --cached --check

Stage the exact files listed by the task and commit with the exact message
stated by the task. The implementer then reports the local commit, checks, and
acceptance summary to the controller and stops. The controller reviews the
task against its acceptance criteria before pushing the exact branch, opening
its PR against main, waiting for the test check, inspecting failures if any,
merging the PR, verifying the issue closed, and fetching origin/main. No task
may merge before that review, and only the controller starts the next task.
