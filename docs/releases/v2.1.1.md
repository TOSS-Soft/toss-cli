# TOSS CLI v2.1.1

TOSS CLI v2.1.1 prepares the release candidate for the completed test-efficiency
work. It keeps public CLI behavior, contracts, durability guarantees, and
release authority unchanged.

## Test lanes

Test ownership is explicit and deterministic. Fast, integration, end-to-end,
package, and release lanes each select their manifest-owned entries, while the
full lane runs the complete unique ownership union.

## Contributor workflow

Contributors can use the focused lane that matches their change for fast
feedback, while pull requests, prepack, and release validation retain the
canonical full suite.

## Internal cold start

Internal contract-validator cold-start work reduces validation-test setup so
contributors receive feedback sooner. This is internal test efficiency, not a
claim about public CLI or user-workload runtime.

## Durability and concurrency

Durable storage tests reduce repeated amplification and use bounded
concurrency. The durable behavior, recovery guarantees, and filesystem-safety
contracts remain unchanged.

## Compatibility

The Node.js engine floor remains `>=20`. Existing bootstrap and scaffold entry
points retain their established behavior:

- `toss init [project-brief.yaml]`
- `toss create <project-brief.yaml>`
- `toss "Project Name" [legacy scaffold options]`
