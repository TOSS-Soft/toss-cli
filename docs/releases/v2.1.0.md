# TOSS CLI v2.1.0

TOSS CLI v2.1.0 delivers the provider-neutral Agent Contract Protocol pipeline
from governed project input through audited, readiness-gated issue publication.
It also adds a risk-based UI/UX lifecycle whose verified repository artifacts,
approvals, and Design Definition of Ready remain bound to the exact source
revisions they authorize.

## Contracts

- ACP v1 defines canonical JSON, stable entity identities, immutable revisioned
  artifact envelopes, provenance, and fail-closed schema/version handling.
- Common schemas and semantic validation cover entities, references, questions,
  provenance, artifact graphs, and lossless YAML projection.
- PM analysis, architecture/ADR, issue plan, specification audit, decisions,
  traceability, state transition, readiness, publication, command-result, and
  design documents are explicit versioned contracts.
- Ownership remains separated: PM owns product requirements, Architect owns
  technical decisions, and Spec/Design Auditors report findings without
  rewriting their source artifacts.

## Pipeline

- Project and feature preparation now advance through deterministic,
  resumable stages backed by verified immutable artifacts.
- Blocking ambiguity packages, exact-revision ADR approvals, specification
  audits, requirement-to-acceptance-criterion traceability, and 100% Project
  Definition of Ready coverage stop unsafe publication.
- Issue preview is read-only. Publication is dry-run by default, idempotent,
  recoverable after partial failure, and gated on the current audit, readiness,
  state, authority, and source revisions.
- Trace, status, readiness, audit, and plan views expose stable human and JSON
  outputs for interactive use and automation.

## CLI

- Project lifecycle: `toss project create|analyze|prepare|status|resume`.
- Feature lifecycle: `toss feature add|analyze|prepare|status`.
- Governance gates: `toss decisions`, `toss architecture`, `toss plan`,
  `toss audit`, `toss readiness`, and `toss issues`.
- Inspection: `toss trace`, `toss artifacts`, and `toss validate`.
- Shared `--from`, `--non-interactive`, `--json`, `--continue`, and `--project`
  options support file-driven and resumable automation without weakening gates.

## Design

- Twelve ACP-backed UI/UX artifact contracts cover the design brief through
  final design approval, including flows, information architecture,
  wireframes, direction, design systems, screens, prototypes, usability
  evidence, and audit results.
- UI work is classified as Lite, Standard, or Critical; backend-only work may
  be explicitly Not Applicable. Downgrades and Not Applicable decisions remain
  evidence- and authority-bound rather than caller-trusted.
- Verified company Design System bindings and production asset manifests keep
  repository artifacts canonical and tamper-evident.
- Design Auditor and UI Design Definition of Ready operate independently from
  Project Definition of Ready. UI-impacting issues require current, exact
  design approval and readiness references before publication.

## Safety

- Corrupt, unknown, stale, ambiguous, unapproved, unaudited, or incomplete
  inputs fail closed before external mutation.
- Preparation commands do not write to GitHub; `toss issues publish` remains a
  dry-run unless explicit `--apply` authority passes every gate.
- No model provider, API key, registry token, or network model call is embedded
  in the contracts or pipeline. Release verification never prints tokens.
- Immutable mappings, deterministic idempotency markers, atomic artifact
  storage, integrity checks, and resumable state make interruption recoverable.

## Compatibility

The Node.js engine floor remains 20. Existing bootstrap and scaffold entry
points keep their established behavior and remain covered by the smoke suite:

- `toss init [project-brief.yaml]`
- `toss create <project-brief.yaml>`
- `toss "Project Name" [legacy scaffold options]`

Existing generated-project governance v2 behavior and raw `toss trace
<ENTITY-ID> [--json]` compatibility are retained alongside the new lifecycle
router.

## Verification

The release-candidate gate installs from the lockfile with
`npm ci --no-audit --no-fund`, runs the focused v2.1.0 release contract and the
complete `npm test` suite, exercises the real smoke and release workflow
contracts, validates the package with `npm pack --dry-run`, and rejects
whitespace or scope drift with Git diff checks. Publication remains deferred
until the reviewed issue branch is merged to `main`, merged-main CI passes, and
the controller validates the exact annotated tag metadata.
