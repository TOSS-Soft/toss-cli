# TOSS CLI v2.1.2

TOSS CLI v2.1.2 introduces the authority-bound organizational lifecycle for
coordinating work and repository releases while preserving the existing CLI
entry points and package compatibility.

## Organizational control

The release adds immutable control-ledger records, explicit operation intents,
receipt-backed execution, deterministic replay, and conflict-safe recovery.
Organization and repository registration now share one validated authority
boundary instead of relying on ambient mutable state.

## Work lifecycle

Projects, epics, features, bugs, reviews, dependencies, branches, and pull
requests can be planned and advanced through closed state transitions. Visible
status and gate values are derived from verified Work and Project evidence.

## Release programs

Repositories can be grouped into deterministic release programs with semantic
version selection, staged activation, patch interruption, approval,
publication verification, and atomic roll-forward to the next program.
Restarted commands consume immutable evidence and do not repeat completed
remote work.

## Safety and compatibility

Hostile, stale, ambiguous, or partial evidence fails closed before later
mutations. Existing package entry points remain available and the Node.js
engine floor remains `>=20`:

- `toss init [project-brief.yaml]`
- `toss create <project-brief.yaml>`
- `toss "Project Name" [legacy scaffold options]`

## Verification

The candidate is verified by the complete test manifest on Node.js 20 and 24,
the independent fast, integration, end-to-end, package, and release lanes,
manifest and boundary integrity checks, and a dry-run package inventory.
